EVIDENCE / ONE-CLICK SELF-AUDIT

Don't trust us.
Verify it yourself.

Every sealed scorecard carries a signed, hash-chained evidence bundle. This page downloads the bundle and checks it entirely in your browser: the event chain is rebuilt from scratch, the root is compared to the one the seal covers, and the Ed25519 signature is verified against the public key published in the repo. No server round-trip decides the verdict — you can do the same with the Node walkthrough in API DOCS.

RUN VERIFIER

Verify a scorecard's evidence

Paste a run id (the hex id in a scorecard URL, e.g. /scorecards/<run id>).

Paste a run id and press VERIFY SIGNATURE. Or run TAMPER DEMO to see a mutated bundle rejected.

WHAT THE VERIFIER CHECKS

Four independent checks, in order

1. Event chain rebuilt — each replay step's hash is recomputed (canonical sorted-key JSON → SHA-256, chained from genesis). Any edit to any event breaks the chain.

2. Events root matches — the final hash must equal the eventsRoot the seal was computed over, so the signature is provably about this ledger.

3. Ed25519 seal valid — the signature is verified in WebCrypto against the published public key 17f868001b3ad45cc67a069e1115c1e8390debe4ad21add712477d91c857827a (same value as functions/_evidence.js, cross-checked by test).

4. Signature covers the scorecard — run id, score and total are inside the signed payload, so a displayed scorecard cannot differ from what was signed.

The public key is embedded in this page's JS (/verify.js); if it ever drifted from the repo-published key, test/verifypage.test.mjs fails the build.
